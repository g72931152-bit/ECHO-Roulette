# ELVAR — v1 / 0.12

ELVAR — сервис случайных видеосвязей с серверной регистрацией, WebRTC, жалобами, избранным, публичными группами и закрытой админ-панелью.

## Что изменено в этой пересборке

- Сохранён фирменный интерфейс без декоративных «человечков».
- Фавикон, apple-touch-icon и логотип используют одну фирменную ELVAR-графику.
- Добавлена регистрация и вход по email + паролю. Пароли не хранятся в открытом виде: сервер использует PBKDF2 + соль.
- Все увиденные профили синхронизируются с Durable Object: администратор видит зарегистрированные аккаунты и гостевые профили, которые уже заходили в сервис.
- В админке есть поиск по имени/email/ID, фильтр по стране, фильтр «только онлайн», статистика, бан, снятие бана, принудительный переход к следующему собеседнику и удаление аккаунта.
- Жалобы сохраняются с категорией, деталями и количеством жалоб от отправителя; список пользователей с жалобами агрегируется отдельно.
- После нескольких жалоб (начиная с 5-й) интерфейс явно требует более подробного описания; категории отображаются крупными кнопками с иконками.
- Все жалобы и feedback отправляются владельцу через Cloudflare Email binding, когда binding настроен.
- Добавлены «Группы» и «Избранное». Избранные собеседники сохраняются между устройствами после входа в аккаунт. Группы публичные, имеют описание и теги; участники могут входить и выходить.
- Секретная комбинация открывает только форму admin unlock. Реальная проверка выполняется сервером по `ADMIN_TOKEN` — секрет не находится в клиентском коде.
- Добавлена генерация сильного локального admin-секрета через `npm run admin:generate`.

## Запуск

```text
npm install
npm run admin:generate
npm run check
npx wrangler dev
```

## Production secrets

Задай секрет Worker `ADMIN_TOKEN`. Адрес владельца по умолчанию: `ptornsaso0@gmail.com`; его можно переопределить `ADMIN_EMAIL`.

Для email-доставки нужен настроенный Cloudflare Email binding `EMAIL` и адрес отправителя `SUPPORT_FROM`.

## WebRTC

Сигнализация и matchmaking идут через Durable Object `Lobby`, медиа — напрямую между браузерами. Для сложных NAT/корпоративных сетей production-конфигурации может понадобиться TURN.
